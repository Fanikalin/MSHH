# Формат репозитория модуля MSHH (для установки по ссылке)

Менеджер модулей («Настройки» → `m` → «Добавить модуль» → «Добавить по
ссылке») умеет устанавливать модуль из любого git-репозитория, оформленного по
этой спецификации.

## Ссылка

* Формат: обычный git-URL: `https://host/user/repo.git`, `git@host:user/repo.git`.
* Опциональный подкаталог после `#`: `https://host/user/repo.git#modules/myproto` —
  если модуль лежит не в корне репозитория, а в подкаталоге.
* Клонирование: `git clone --depth 1 <ссылка>` — ветка по умолчанию.

## Что должно лежать в репозитории

Git-репозиторий содержит **один или несколько крейтов-модулей**. Ядро ищет
крейты с условием «`[lib] crate-type` содержит `cdylib`» на глубине до трёх
каталогов от корня (или от `#подкаталога`).

Минимальный крейт:

```
myproto/
├── Cargo.toml
└── src/
    └── lib.rs
```

`Cargo.toml`:

```toml
[package]
name = "mshh-module-myproto"      # имя станет именем файла lib<name>.so
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
mshh-module-api = "2"             # ABI v2 (git/path — см. docs/MODULES.md)
```

`src/lib.rs` — минимум (полный гайд: [MODULES.md](MODULES.md)):

```rust
use mshh_module_api::prelude::*;

#[derive(Default)]
struct MyProto;

impl Module for MyProto {
    fn run(&self, s: Session) {
        // Профиль (несколько аккаунтов одного протокола):
        let profile = s.profile();
        // Таблицы: mod_myproto_{profile}_... ; kv: "{profile}_ключ".
    }

    fn settings_schema(&self) -> Vec<FieldDef> {
        vec![] // настройки профиля в «Настройках» (опционально)
    }
}

register_module!(MyProto, id: "myproto", name: "MyProto", version: "0.1.0");
```

## Требования ядра при загрузке

1. **Хендшейк ABI**: экспорт `mshh_abi_version()` должен вернуть версию,
   совпадающую с версией ядра (сейчас `2`). Несовпадение — модуль не грузится.
2. **Экспорт** `mshh_module_info` — id/name/version (генерирует макрос
   `register_module!`); `mshh_module_settings` — опционально (схема настроек).
3. **Изоляция профилей**: таблицы `mod_<id>_<profile>_…`, kv с префиксом
   профиля — ядро может запустить несколько экземпляров вашей библиотеки.
4. **Гигиена**: `run()` не паникует, завершается по `Ev::Shutdown` за <1 с,
   ошибки сети — `Toast` + retry (см. MODULES.md «Правила и ограничения»).

## Что делает ядро при установке

1. `git clone --depth 1` в `data/modules-src/repo-<hash>/`.
2. Поиск cdylib-крейтов (если несколько — берёт первый, сообщая об этом).
3. `cargo build --release` в каталоге крейта.
4. Копирование артефакта (`lib<name>.so`; дефисы имени пакета становятся
   подчёркиваниями) в `data/modules/`.
5. Загрузка библиотеки, создание профиля по умолчанию (имя = имя модуля),
   запуск экземпляра. Дальше — «Настройки»: сессии/логины через формы модуля.

Ошибки любого шага (нет git/cargo, сборка сломана, крейтов не найдено) —
`Toast` с последними строками вывода; установленный ранее файл не трогается.

## Обновление и удаление

* Повторная установка по той же ссылке перекачивает и пересобирает поверх.
* Удаление — в менеджере не реализовано (v1): удалите `.so` из
  `~/.local/share/mshh/modules` и перезапустите; профиль удалите в «Настройках».

## Безопасность

Модуль — **нативный код с полным доступом к процессу и вашим данным**, как мод
к игре. Ядро НЕ изолирует модули и НЕ проверяет код из ссылок: в менеджере
такой модуль помечается красным «неизвестный» до внесения в вшитый каталог
доверия. Ставьте только репозитории, которым доверяете; предпочтение —
репозитории с открытым кодом (за опенсоурс идёт плюс в карму рейтинга).
