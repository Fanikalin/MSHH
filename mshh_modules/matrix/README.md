// Модуль Matrix для MSHH (runtime: renderer)

## Что делает

Подключает аккаунт Matrix к единому списку чатов MSHH. В отличие от остальных
модулей, у Matrix нет раннера в main-процессе: мост работает прямо в
рендерере (`src/mshh/bridges/matrix.ts`) и переиспользует matrix-js-sdk,
который уже есть в бандле Cinny (та же учётная запись и то же устройство).

Модуль публикует в единый список MSHH только метаданные чатов (название,
время последней активности, счётчик непрочитанных). Сами сообщения и
переписка остаются в нативном интерфейсе Cinny: клик по чату Matrix открывает
родное окно комнаты Cinny.

## Как войти

В карточке профиля заполните три поля формы (она генерируется из манифеста):

- **Homeserver** — адрес домашнего сервера, например `https://matrix.org`.
- **Имя пользователя** — локальная часть (`user`) или полный
  Matrix ID (`@user:matrix.org`); недостающие части дописываются автоматически.
- **Пароль** — пароль учётной записи.

Токен доступа сохраняется в localStorage (`mshh_matrix_bridge_<profileId>`)
и переиспользуется при следующих запусках; повторный логин выполняется только
если токен протух, а пароль ещё известен. Данные синхронизации хранятся
в собственных IndexedDB-базах `mshh-matrix-bridge-<profileId>` /
`mshh-matrix-bridge-crypto-<profileId>` и не пересекаются с хранилищем
родной сессии Cinny.

## Шифрованные чаты

Зашифрованные комнаты видны в едином списке MSHH как заглушки (название и
счётчик непрочитанных — без превью сообщений). Открываются они в родном
чат-вью Cinny, где расшифровка работает штатно: мост не инициализирует
собственное e2e-шифрование и не пытается читать содержимое зашифрованных
комнат, чтобы не конфликтовать с сессией Cinny.

## Прочее

- Аватарки чатов в едином списке не подтягиваются (мост не использует
  `mshh-media`); UI показывает цветную букву-инициал.
- Возможности по манифесту: медиа — нет, история — через нативный Cinny,
  «печатает» — нет (только метаданные).
